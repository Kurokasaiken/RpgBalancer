# CDA-09-001 — Modding Layer

## Context
Phase 09-001 of Config-Driven Architecture (CDA-MASTER-001). Implements the modding layer with registry, loader, validator, sandbox, and UI.

## Objectives
- Create modding registry
- Create modding loader
- Create modding validator
- Create modding sandbox
- Create modding UI
- Add unit tests for modding layer
- Verify modding layer integration

## Scope

### Files to Create
- `src/modding/registry/**` — Modding registry
- `src/modding/loader/**` — Modding loader
- `src/modding/validator/**` — Modding validator
- `src/modding/sandbox/**` — Modding sandbox
- `src/modding/ui/**` — Modding UI
- `tests/unit/modding/**/*.test.ts` — Unit tests

### Files to Modify
- (None — standalone phase)

### Out of Scope
- AI Production Pipeline (deferred to CDA-10-001)

## Guardrails

### Invariants
- **Config-first**: All modding parameters in config
- **Security**: Sandbox must isolate mods from core system
- **Validation**: All mods must be validated before loading

### Constraints
- Modding layer must integrate with CDA-01-08
- Sandbox must be secure
- Tests must cover all modding scenarios
