## Goal

Il `FloatingPanel` "Planner" — il laboratorio reversibile della spedizione. Separazione netta **INPUT | OUTPUT**.

## Deliverable

- **Layout 2 colonne** (ricerca UI 2026-09-30): INPUT a sinistra (PARTY + LOADOUT), OUTPUT a destra; stacked sotto ~800px. Non bloccante (`FloatingPanel` v4).
- **INPUT**:
  - PARTY: slot rack esistente (`useResidentSlotController` + roster da `src/ui/idleVillage/roster/index.ts`); **risk badge** per membro (pattern XCOM — il rischio personale si vede già nello slot);
  - LOADOUT: `EquipSlotRack`/`ConsumablePile`/`EquippableItemCard` (v10) **cablati alle stat via MP-03** — verificare cosa coprono davvero prima di riusare; se mancano interazioni reali (select/validazione slot), estendere via props, mai duplicare.
- **OUTPUT**:
  - headline: Successo / Ferita / Morte / Durata / Reward — barre stacked per i rischi (pattern Darkest Dungeon), Durata come barra con ticks (pattern Frostpunk);
  - **delta** `old → new` colorato + freccia, `aria-live="polite"`, animazione ≤300ms;
  - **BY MEMBER**: blocco dedicato sempre visibile, righe per membro con injury/death (rev.2 — mai solo aggregato);
  - **WHY**: pannello "Insight" collassabile (chiuso di default) + tooltip sui valori; righe per metrica in catene causa→effetto dai `contributions` (`+ Companion → + Strength → − injury risk`) — niente log tecnico;
  - **Undo** (ultimo cambio, toast) e **Reset to baseline** — primitive di MP-04.
- **Stati**: bozza vuota, `canEmbark` false (con motivo), residente invalidato a runtime, party > cap, touch (tap-to-open al posto di hover).
- **Perf**: ricalcolo memoizzato + debounce ~100ms; niente calcolo nel render path critico.
- **i18n**: tutte le stringhe `useTranslation` (`idleVillage`), incluso il template WHY; **skin**: primitive + `skinConfigRegistry`, zero `.css` standalone, zero colori letterali.
- **Telemetry**: `mission_planner_open`, `_party_change`, `_loadout_change`, `_undo`, `_reset`, `_launch` con payload definito.

## Acceptance

- Nessun "Simula": ogni modifica aggiorna subito l'OUTCOME (test RTL).
- Test: separazione INPUT/OUTPUT renderizzata; BY MEMBER sempre presente; WHY mostra catene non numeri grezzi; delta compare dopo una modifica; Undo/Reset ripristinano outcome identici (con `serializeOutcome`).
- Smoke route 200 + Playwright in MP-07.
