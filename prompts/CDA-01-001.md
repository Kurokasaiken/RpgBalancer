# CDA-01-001 — Component Runtime (registry/factory/resolver/validation)

## Context
Phase 01-001 of Config-Driven Architecture (CDA-MASTER-001). Implements the component runtime with registry, factory, resolver, and validation system.

## Objectives
- Create ComponentRegistry
- Create ComponentFactory
- Create ComponentDefaultResolver
- Create ValidationSystem
- Add unit tests for component runtime

## Scope

### Files to Create
- `src/game/runtime/ComponentRegistry.ts` — Component registry
- `src/game/runtime/ComponentFactory.ts` — Component factory
- `src/game/runtime/ComponentDefaultResolver.ts` — Component default resolver
- `src/game/runtime/ValidationSystem.ts` — Validation system
- `tests/unit/game/runtime/ComponentRegistry.test.ts` — Unit tests
- `tests/unit/game/runtime/ComponentFactory.test.ts` — Unit tests
- `tests/unit/game/runtime/ComponentDefaultResolver.test.ts` — Unit tests
- `tests/unit/game/runtime/ValidationSystem.test.ts` — Unit tests

### Files to Modify
- (None — standalone phase)

### Out of Scope
- Rendering Primitive System (deferred to CDA-02-001)

## Guardrails

### Invariants
- **Config-first**: No hardcoded switch/case on component types
- **i18n**: i18n contracts per component
- **Skin contracts**: Skin contracts per component

### Constraints
- Component runtime must be config-driven
- No hardcoded component type logic
- Tests must cover all runtime scenarios

## Implementation Plan

### Step 1: Create ComponentRegistry
Create `ComponentRegistry.ts` with:
- Registry for component types
- Config-driven component registration
- Component lookup by type

### Step 2: Create ComponentFactory
Create `ComponentFactory.ts` with:
- Factory for component instantiation
- Config-driven component creation
- Component lifecycle management

### Step 3: Create ComponentDefaultResolver
Create `ComponentDefaultResolver.ts` with:
- Default resolution logic for components
- Config-driven resolution parameters
- Component dependency resolution

### Step 4: Create ValidationSystem
Create `ValidationSystem.ts` with:
- Validation for component configs
- Config-driven validation rules
- Component contract validation

### Step 5: Add Unit Tests
Create comprehensive tests for all runtime components

### Step 6: Verify Integration
- Ensure component runtime works with config
- Test with realistic component scenarios
- Validate config integration
