# CDA-00-005 — World surface controller integration

## Context
Phase 005 of Component-Based World Surface Architecture. Integrates the component-based world surface with the world surface controller (IV-WSC) for unified management.

## Objectives
- Integrate ECS runtime with world surface controller
- Add controller hooks for component-based entities
- Add unit tests for controller integration
- Verify unified world surface management

## Scope

### Files to Create
- `src/engine/worldSurface/controllerIntegration.ts` — Controller integration layer
- `tests/unit/worldSurface/controllerIntegration.test.ts` — Unit tests

### Files to Modify
- `src/engine/game/idleVillage/WorldSurfaceController.ts` — Add component-based hooks

### Out of Scope
- UI integration (already covered in CDA-00-003)
- Telemetry integration (deferred to CDA-00-004)

## Guardrails

### Invariants
- **Config-first**: All controller parameters in Zod schema
- **Persistence**: Use `PersistenceService` for any state
- **i18n**: Any user-facing strings must use `common` namespace
- **No standalone CSS**: Skin tokens only (not applicable to this phase)

### Constraints
- Controller integration must not break existing IV-WSC logic
- Component-based entities must work with controller hooks
- Tests must cover all integration scenarios

## Implementation Plan

### Step 1: Define Controller Integration Schema
Create Zod schema for controller integration:
- `ControllerIntegrationConfig` — hook priorities, entity sync parameters
- Validation helpers for config values

### Step 2: Implement Controller Integration
Create `controllerIntegration.ts` with:
- `registerComponentEntity(entity, controller)` — register component entity with controller
- `syncComponentEntities(controller)` — sync component entities with controller state
- Config-driven integration parameters

### Step 3: Integrate with World Surface Controller
Modify `WorldSurfaceController.ts` to:
- Add hooks for component-based entities
- Support both legacy and component-based entities
- Maintain backward compatibility

### Step 4: Add Unit Tests
Create comprehensive tests in `controllerIntegration.test.ts`:
- Integration correctness tests (known inputs/outputs)
- Controller hook tests (register, sync)
- Backward compatibility tests (legacy entities still work)
- Config sensitivity tests (changing parameters changes behavior)
- Edge case tests (max entities, sync failures)

### Step 5: Verify Integration
- Ensure controller integration works with ECS runtime
- Test with realistic controller scenarios
- Validate config integration
