## Implementation Plan

### Step 1: Define Telemetry Events
Create `worldSurfaceTelemetry.ts` with:
- Zod schemas for world surface events (entity_created, component_added, component_removed, entity_updated)
- Helper functions to emit telemetry events
- Integration with existing analytics infrastructure

### Step 2: Add Telemetry to World Surface
Hook telemetry into world surface system:
- Emit `entity_created` event when entity is created
- Emit `component_added` event when component is added
- Emit `component_removed` event when component is removed
- Emit `entity_updated` event when entity is updated

### Step 3: Create End-to-End Tests
Create comprehensive tests in `componentBasedWorldSurface.test.ts`:
- Test case for complete world surface flow (entity → component → update → destroy)
- Verification of component lifecycle at each step
- Verification of entity queries and filtering
- Edge case tests (max entities, max components, etc.)
- Config validation tests

### Step 4: Update Plan Document
Update `component_based_world_surface_plan.md`:
- Add changelog entry for 001-004 completion
- Document any deviations from original plan
- Update status to "completed"
- Add evidence log references

### Step 5: Verify Safeguards
Run all safeguards:
- `npm run lint -- src/engine/worldSurface src/analytics/common src/ui/common`
- `npm run test -- tests/unit/worldSurface/componentBasedWorldSurface.test.ts`
- `npm run build:check`
- `npm run kanban:lint`
