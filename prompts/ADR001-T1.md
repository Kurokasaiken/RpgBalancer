# ADR001-T1 — Canonical quest event schema (E1) + RngService

## Context
Phase T1 of Quest Engine Reconciliation (ADR-001). Implements the canonical quest event schema (E1) and RngService for deterministic quest resolution.

## Objectives
- Create canonical quest event schema (E1)
- Implement RngService for deterministic RNG
- Add quest config schema
- Add unit tests for RngService and QuestEvent

## Scope

### Files to Create
- `src/engine/quest/QuestEvent.ts` — Canonical quest event schema
- `src/engine/quest/RngService.ts` — Deterministic RNG service
- `src/balancing/config/idleVillage/questConfig.ts` — Quest config schema
- `tests/unit/engine/RngService.test.ts` — RngService unit tests
- `tests/unit/engine/QuestEvent.test.ts` — QuestEvent unit tests

### Files to Modify
- (None — standalone phase)

### Out of Scope
- Resolution engine (deferred to T2)
- ActivityDefinition migration (deferred to T3)

## Guardrails

### Invariants
- **Config-first**: All quest parameters in Zod schema
- **Persistence**: Use `PersistenceService` for seed/state (no localStorage)
- **i18n**: Any user-facing strings must use `idleVillage` namespace
- **No standalone CSS**: Skin tokens only (not applicable to this phase)

### Constraints
- RngService must be deterministic (same seed = same sequence)
- Quest event schema must be JSON-serializable
- Tests must cover all RNG scenarios

## Implementation Plan

### Step 1: Define Quest Event Schema
Create `QuestEvent.ts` with:
- Zod schema for quest events (E1 canonical form)
- Event types: quest_started, quest_completed, quest_failed, quest_abandoned
- Event payload structure (questId, timestamp, outcome, rewards)
- Validation helpers for event values

### Step 2: Implement RngService
Create `RngService.ts` with:
- Deterministic RNG implementation (seeded)
- `setSeed(seed)` — set RNG seed
- `next()` — generate next random number
- `nextFloat()` — generate next float in [0, 1)
- `nextInt(min, max)` — generate next int in [min, max)
- Seed persistence via PersistenceService

### Step 3: Define Quest Config Schema
Create `questConfig.ts` with:
- Zod schema for quest configuration
- Quest difficulty parameters
- Quest reward parameters
- Quest risk parameters
- Validation helpers for config values

### Step 4: Add Unit Tests
Create comprehensive tests:
- `RngService.test.ts`: deterministic RNG tests, seed persistence, edge cases
- `QuestEvent.test.ts`: event schema validation, serialization, edge cases

### Step 5: Verify Integration
- Ensure RngService is deterministic
- Test with realistic quest scenarios
- Validate config integration
