# MP-02 — Mission Planner: schema item/loadout + fix data model fasi (config)

> Piano: `plans/PLAN-018-mission-planner.md` v3 §T-002 + spec `mission_planner_math_spec.md` (MP-00).
> Master: `prompts/PLAN-018-mission-planner.md`. blocked_by: **MP-00**.

## Goal

Creare lo schema Zod canonico per item/equip/consumabili e correggere il data model delle fasi di quest (stat del check).

## Deliverable

1. **Schema Zod item** in `src/balancing/config/idleVillage/` (nuovo modulo, es. `questItems.schema.ts`):
   - campi: `id`, `slot: 'weapon'|'armor'|'mount'|'trinket'` (enum da config `EQUIP_SLOTS`), `statDeltas: Record<string, number>`, `injuryChanceDelta`, `deathChanceDelta`, `rewardMultiplierDelta`, `durationDelta`, `durationMult`, `coverRiskDelta` (D1 approvato: pp applicati agli **altri** membri), `qty` per consumabili;
   - regole: un item per slot per membro; consumabili = pool party con quantità (D3).
2. **Pool di esempio** nel file config (non TS-sparso): almeno una **cavalcatura** (`durationMult: 0.5` indicativo — il valore esatto arriva dal report MP-00), un'arma con `statDeltas`, un'armatura con `deathChanceDelta` negativo e/o `durationDelta` positivo, un consumabile con `injuryChanceDelta`/`rewardMultiplierDelta`.
3. **Fix data model fasi**:
   - `questBlueprints.schema.ts`: aggiungere `checkStatTags: string[]` al requirement di fase (accanto a `statRequirement`, che resta gate);
   - `questSkillCheckConfig.ts`: aggiungere `partyStatMult` (Zod, default dal report MP-00);
   - `questBlueprints.ts`: re-author — `checkStatTags` coerenti col tipo di fase (fight → `strength`/`damage`, trap → `perception`/`agility`, explore → `perception`, dialogue → `charisma`… mappatura definita nella spec MP-00);
   - `questMilestones.ts`: `resolvePhaseStatTags` legge `checkStatTags` prima, poi fallback su `requiredStatTags` (NON più su `statRequirement.allOf` come stat — quello resta solo per il gate `statMatching`).
4. Adattare `buildAstrolabeSkillsForPhase` al nuovo campo + `partyStatMult` (retrocompatibile: blueprint senza `checkStatTags` mantengono il comportamento attuale o un default dichiarato nella spec).

- `npm run lint -- src/balancing src/engine` e `npm run kanban:lint` verdi.
