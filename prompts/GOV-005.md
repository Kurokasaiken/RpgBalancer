OBIETTIVO
Confrontare `src/docs/docs/idle_village/COMPONENT_MASTER_INDEX.md` con `src/ui/idleVillage/frozen/registry.ts` (`KIT_REGISTRY`) e produrre un audit documentale che elenchi discrepanze, voci mancanti e suggerimenti di correzione.

FILE TARGET
1. `src/docs/docs/idle_village/COMPONENT_MASTER_INDEX.md` (read)
2. `src/ui/idleVillage/frozen/registry.ts` (read)
3. `src/docs/docs/idle_village/COMPONENT_MASTER_INDEX_AUDIT.md` (new)

OPERAZIONI DA ESEGUIRE
1. Leggi `COMPONENT_MASTER_INDEX.md` e `KIT_REGISTRY`.
2. Per ogni entry in `KIT_REGISTRY` (sia `certified` che `draft`):
   - Verifica se esiste una riga corrispondente in `COMPONENT_MASTER_INDEX.md`.
   - Verifica se esiste il `docPath` referenziato (se specificato).
   - Verifica se esiste `certManifestPath` (se specificato).
   - Verifica coerenza tra `status` e `last certified`.
3. Per ogni riga in `COMPONENT_MASTER_INDEX.md`:
   - Verifica se esiste un `kitId` corrispondente in `KIT_REGISTRY`.
   - Verifica se il `*_trusted.md` linkato esiste.
   - Verifica se la data `last certified` è coerente con la data dell'evidence log citato.
4. Crea `COMPONENT_MASTER_INDEX_AUDIT.md` con una tabella Markdown che riporta:
   - `Component / Contract`
   - `KIT_REGISTRY status`
   - `MASTER_INDEX status`
   - `Doc found`
   - `Cert manifest found`
   - `Issue` (e.g. `missing kitId`, `missing trusted doc`, `stale date`, `status mismatch`, `OK`)
   - `Recommended action`
5. Aggiungi un riepilogo in coda: totale voci, voci OK, voci con problemi, elenco issue per priorità.

OPERAZIONI VIETATE
- Non modificare `COMPONENT_MASTER_INDEX.md` in questo task (sarà GOV-006).
- Non modificare `KIT_REGISTRY`.
- Non creare nuovi file trusted doc.
