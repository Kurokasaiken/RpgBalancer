# ADR001-T2 — Build deterministic resolution engine (E2)

## Context
Phase T2 of Quest Engine Reconciliation (ADR-001). Implements the deterministic resolution engine (E2) for quest outcomes.

## Objectives
- Create QuestResolutionEngine for deterministic quest resolution
- Implement resolvers for different quest types
- Add unit tests for resolution engine
- Verify deterministic outcomes

## Scope

### Files to Create
- `src/engine/quest/QuestResolutionEngine.ts` — Resolution engine
- `src/engine/quest/resolvers/*.ts` — Quest type resolvers
- `tests/unit/engine/QuestResolutionEngine.test.ts` — Unit tests

### Files to Modify
- (None — standalone phase)

### Out of Scope
- ActivityDefinition migration (deferred to T3)
- Math.random() purge (deferred to T4)

## Guardrails

### Invariants
- **Config-first**: All resolution parameters in Zod schema
- **Persistence**: Use `PersistenceService` for seed/state (no localStorage)
- **i18n**: Any user-facing strings must use `idleVillage` namespace
- **No standalone CSS**: Skin tokens only (not applicable to this phase)

### Constraints
- Resolution engine must be deterministic (same seed = same outcome)
- Resolvers must use RngService from T1
- Tests must cover all resolution scenarios

## Implementation Plan

### Step 1: Define Resolution Engine
Create `QuestResolutionEngine.ts` with:
- `resolveQuest(quest, seed)` — resolve quest with deterministic outcome
- Integration with RngService from T1
- Config-driven resolution parameters
- Error handling for invalid quests

### Step 2: Implement Resolvers
Create resolvers in `resolvers/`:
- `CombatQuestResolver.ts` — resolve combat quests
- `ExplorationQuestResolver.ts` — resolve exploration quests
- `SocialQuestResolver.ts` — resolve social quests
- `CraftingQuestResolver.ts` — resolve crafting quests
- Each resolver uses RngService for deterministic outcomes

### Step 3: Add Unit Tests
Create comprehensive tests in `QuestResolutionEngine.test.ts`:
- Deterministic resolution tests (same seed = same outcome)
- Resolver correctness tests (known inputs/outputs)
- Config sensitivity tests (changing parameters changes outcomes)
- Edge case tests (invalid quests, edge parameters)

### Step 4: Verify Integration
- Ensure resolution engine is deterministic
- Test with realistic quest scenarios
- Validate config integration
