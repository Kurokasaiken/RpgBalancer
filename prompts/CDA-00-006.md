# CDA-00-006 — Performance optimization + profiling

## Context
Phase 006 of Component-Based World Surface Architecture. Implements performance optimizations and profiling tools for the component-based world surface system.

## Objectives
- Add performance profiling for ECS runtime
- Implement entity pooling for performance
- Add component pooling for performance
- Add unit tests for performance optimizations

## Scope

### Files to Create
- `src/engine/worldSurface/performanceProfiler.ts` — Performance profiling tools
- `src/engine/worldSurface/entityPool.ts` — Entity pooling system
- `src/engine/worldSurface/componentPool.ts` — Component pooling system
- `tests/unit/worldSurface/performanceProfiler.test.ts` — Unit tests

### Files to Modify
- `src/engine/worldSurface/ecsRuntime.ts` — Integrate pooling

### Out of Scope
- UI integration (already covered in CDA-00-003)
- Telemetry integration (already covered in CDA-00-004)

## Guardrails

### Invariants
- **Config-first**: All performance parameters in Zod schema
- **Persistence**: Use `PersistenceService` for any state (though this phase is performance-only)
- **i18n**: Any user-facing strings must use `common` namespace
- **No standalone CSS**: Skin tokens only (not applicable to this phase)

### Constraints
- Performance optimizations must not break existing ECS logic
- Pooling must be configurable, not hardcoded
- Tests must cover all performance scenarios

## Implementation Plan

### Step 1: Define Performance Config Schema
Create Zod schema for performance parameters:
- `PerformanceConfig` — pool sizes, profiling thresholds, optimization flags
- Validation helpers for config values

### Step 2: Implement Performance Profiler
Create `performanceProfiler.ts` with:
- `startProfiling()` — start performance profiling
- `stopProfiling()` — stop and return profiling results
- `measureComponentUpdate(component, fn)` — measure component update time
- Config-driven profiling parameters

### Step 3: Implement Entity Pool
Create `entityPool.ts` with:
- `acquireEntity()` — acquire entity from pool
- `releaseEntity(entity)` — release entity back to pool
- Config-driven pool size

### Step 4: Implement Component Pool
Create `componentPool.ts` with:
- `acquireComponent(type)` — acquire component from pool
- `releaseComponent(component)` — release component back to pool
- Config-driven pool size

### Step 5: Integrate Pooling with ECS Runtime
Modify `ecsRuntime.ts` to:
- Use entity pool for entity creation
- Use component pool for component creation
- Maintain backward compatibility with non-pooled mode

### Step 6: Add Unit Tests
Create comprehensive tests in `performanceProfiler.test.ts`:
- Profiling correctness tests (known inputs/outputs)
- Pooling tests (acquire, release, pool size)
- Performance tests (measure improvement with pooling)
- Config sensitivity tests (changing parameters changes behavior)
- Edge case tests (pool exhaustion, max pool size)

### Step 7: Verify Integration
- Ensure performance optimizations work with ECS runtime
- Test with realistic performance scenarios
- Validate config integration
