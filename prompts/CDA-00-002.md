# CDA-00-002 — Component-based world surface runtime

## Context
Phase 002 of Component-Based World Surface Architecture. Implements the runtime engine for component-based world surface, with component lifecycle management and entity-component-system (ECS) architecture.

## Objectives
- Create ECS runtime for world surface
- Implement component lifecycle (create, update, destroy)
- Add entity management system
- Add unit tests for ECS runtime

## Scope

### Files to Create
- `src/engine/worldSurface/ecsRuntime.ts` — ECS runtime implementation
- `src/engine/worldSurface/componentManager.ts` — Component lifecycle manager
- `src/engine/worldSurface/entityManager.ts` — Entity management system
- `tests/unit/worldSurface/ecsRuntime.test.ts` — Unit tests

### Files to Modify
- (None — standalone phase)

### Out of Scope
- UI integration (deferred to CDA-00-003)
- Telemetry integration (deferred to CDA-00-004)

## Guardrails

### Invariants
- **Config-first**: All ECS parameters in Zod schema
- **Persistence**: Use `PersistenceService` for any state (though this phase is runtime-only)
- **i18n**: Any user-facing strings must use `common` namespace
- **No standalone CSS**: Skin tokens only (not applicable to this phase)

### Constraints
- ECS runtime must be deterministic (same input = same output)
- Component lifecycle must be configurable, not hardcoded
- Tests must cover all ECS scenarios

## Implementation Plan

### Step 1: Define ECS Config Schema
Create Zod schema for ECS parameters:
- `ECSConfig` — max entities, max components per entity, update frequency
- Validation helpers for config values

### Step 2: Implement ECS Runtime
Create `ecsRuntime.ts` with:
- `createEntity()` — create new entity
- `addComponent(entity, component)` — add component to entity
- `removeComponent(entity, componentType)` — remove component from entity
- `updateEntities(deltaTime)` — update all entities with components
- Config-driven ECS parameters

### Step 3: Implement Component Manager
Create `componentManager.ts` with:
- Component lifecycle management (create, update, destroy)
- Component pooling for performance
- Config-driven component parameters

### Step 4: Implement Entity Manager
Create `entityManager.ts` with:
- Entity lifecycle management (create, destroy)
- Entity queries for component filtering
- Config-driven entity parameters

### Step 5: Add Unit Tests
Create comprehensive tests in `ecsRuntime.test.ts`:
- ECS runtime correctness tests (known inputs/outputs)
- Component lifecycle tests (create, update, destroy)
- Entity management tests (create, destroy, query)
- Config sensitivity tests (changing parameters changes behavior)
- Edge case tests (max entities, max components)

### Step 6: Verify Integration
- Ensure ECS runtime works with component definitions
- Test with realistic ECS scenarios
- Validate config integration
