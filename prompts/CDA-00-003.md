# CDA-00-003 — UI hooks (world surface editor)

## Context
Phase 003 of Component-Based World Surface Architecture. Creates UI hooks and components for world surface editor, with i18n support and skin token styling.

## Objectives
- Create useWorldSurfaceEditor hook for world surface editing
- Create WorldSurfaceEditor component for UI
- Add component editing capabilities
- Add i18n strings for world surface UI

## Scope

### Files to Create
- `src/ui/common/hooks/useWorldSurfaceEditor.ts` — World surface editor hook
- `src/ui/common/components/WorldSurfaceEditor.tsx` — World surface editor component

### Files to Modify
- `public/locales/en/common.json` — Add i18n strings for world surface UI

### Out of Scope
- Telemetry integration (deferred to CDA-00-004)

## Guardrails

### Invariants
- **Config-first**: All UI thresholds and labels in config
- **Persistence**: Use `PersistenceService` for world surface state
- **i18n**: All UI strings must use `common` namespace
- **No standalone CSS**: Skin tokens only for component styling

### Constraints
- UI must be responsive and accessible
- World surface editor must use skin tokens, not standalone CSS
- i18n coverage is mandatory for all UI strings

## Implementation Plan

### Step 1: Create useWorldSurfaceEditor Hook
Create `useWorldSurfaceEditor.ts` with:
- Hook for accessing world surface state from ECS runtime
- Computed values for entities, components
- Actions for adding/removing components

### Step 2: Create WorldSurfaceEditor Component
Create `WorldSurfaceEditor.tsx` with:
- Display world surface entities and components
- Controls for adding/removing components
- Component property editing
- Skin token styling (no standalone CSS)
- Accessibility support (ARIA labels)

### Step 3: Add i18n Strings
Add to `common.json`:
- World surface editor labels
- Component type labels
- World surface editor messages

### Step 4: Add Unit Tests
Create comprehensive tests:
- Hook tests (state access, computed values)
- Component tests (rendering, accessibility)
- i18n coverage tests

### Step 5: Verify Integration
- Ensure UI displays world surface state accurately
- Verify skin token styling works correctly
- Test with realistic world surface scenarios
