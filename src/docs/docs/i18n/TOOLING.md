# I18N Tooling Guide

This document describes the localization CLI tooling, key naming conventions and CI integration for the RPG project.

## Key naming convention

- **Format**: `namespace:domain.section.key`
- **Namespace separator**: `:` (colon). Example: `idleVillage:worker.tooltip.bio`.
- **Key separator**: `.` (dot). Example: `worker.tooltip.bio`.
- **Default namespace**: `common` (used when `useTranslation('common')` is called).
- **Domain examples**: `worker`, `slotRack`, `questRisk`, `narrative`, `ftue`, `map`, `scheduler`, `errors`.

Use `t('namespace:key')` or `<Trans i18nKey="namespace:key" />` in source.

## CLI scripts

All scripts live in `scripts/i18n/` and are run with `tsx`.

| Command | Description |
| --- | --- |
| `npm run i18n:extract` | Scan `src/ui/**/*.{ts,tsx}` with `i18next-parser` and write `public/locales/en/$NAMESPACE.json`. |
| `npm run i18n:validate` | Check that every key used in source exists in `public/locales/en/*.json`. Fails on missing keys. |
| `npm run i18n:audit` | Report missing and obsolete keys per namespace. |
| `npm run i18n:build-pseudo` | Generate `public/locales/pseudo/*.json` from English JSON with expansion and accenting. |
| `npm run i18n:types` | Regenerate `src/localization/i18n.types.ts` from `public/locales/en/*.json` using `i18next-resources-for-ts`. |

## CI integration

The GitHub Actions workflow `.github/workflows/i18n-validation.yml` runs on every push or pull request to `main`/`develop` when localization files, sources or tests change.

Steps:

1. `npm run i18n:extract`
2. `npm run i18n:validate`
3. `npm run i18n:types`
4. `npm run i18n:build-pseudo`
5. `npm test -- tests/i18n/i18n.test.ts`
6. `npm run build:check`
7. `npm run kanban:lint`

The `validate` step exits with code `1` if any key used in source is missing in `public/locales/en/*.json`, blocking the PR.

## Testing

Unit tests are in `tests/i18n/i18n.test.ts`. They cover:

- Missing key detection.
- Namespace resolution from `useTranslation`, `namespace:` prefix and `ns` option.
- Pseudo-locale transformation and consistency.
- Key extraction from a temporary source tree.

## Pseudo-locale

Pseudo-locale strings are generated by `pseudoLocalize` in `src/localization/pseudoLocalize.ts`. They are wrapped in `!! ... !!` and accented/expanded to reveal layout overflow before real translations.

## Regenerate everything

```bash
npm run i18n:extract
npm run i18n:validate
npm run i18n:types
npm run i18n:build-pseudo
npm test -- tests/i18n/i18n.test.ts
```

Do not manually edit files under `public/locales/en` or `public/locales/pseudo` that are generated by these commands.
