# Playtest Annotation Assistant

**Task ID:** NP-267  
**Status:** ⛏️ In Progress

## Overview

The Playtest Annotation Assistant augments the mobile playtest logger with rapid note-taking, tag automation, and markdown exports. It is meant to live side-by-side with the existing `PlaytestPanel` so that researchers can pin issues to specific timeline events without leaving the logging screen.

Core goals:

- Config-first experience powered by `annotationConfig.ts`
- Auto-tagging suggestions driven by `eventTaggingRules`
- Quick note templates for recurrent issues (FTUE, crashes, copy, etc.)
- Markdown export that blends annotations, device info, and timeline slices
- Zero magic numbers: UI reads only from config + `PlaytestLogger` data sources

## Architecture Snapshot

## Configuration Contract

All UI-facing values come from `src/ui/playtest/config/annotationConfig.ts`:

```ts
export interface AnnotationAssistantConfig {
  tags: AnnotationTag[];           // palette + shortcuts
  quickNotes: QuickNoteTemplate[]; // label/template/prefilled tags
  severities: Record<AnnotationSeverity, SeverityStyle>;
  timeline: { refreshIntervalMs; maxVisibleEvents; markerSizePx; showEventTypeLegend };
  markdown: { headingLevel; includeSummary; includeTimeline; includeDeviceInfo; includePerformance; footnote? };
  eventTaggingRules: Partial<Record<PlaytestEventType, string[]>>;
}
```

Use `mergeAnnotationConfig(overrides)` to add product-specific tweaks without duplicating defaults.

## Auto Tagging Pipeline

1. Timeline list exposes the last `timeline.maxVisibleEvents` from `PlaytestLogger.getRecentEvents()`.
2. Selecting a row stores `selectedEventId` and exposes `suggestedTags = getAutoTagsForEvent(event, config)`.
3. Designers can either click "Add suggested tags" or manually toggle tags. `dedupe()` guarantees uniqueness.

This keeps heuristics declarative—add new tags or events from config only.

## Quick Notes

`config.quickNotes` defines reusable templates with preloaded tags. When a user taps a chip:

- Title defaults to `note.label` if the field was empty.
- Body becomes `note.template` (can still be edited).
- Tags merge with the current selection.
- UI highlights the active chip for immediate feedback.

## Annotation Creation Flow

1. (Optional) pick a quick note.
2. Enter/update title + description.
3. Choose severity chip (styled via `config.severities`).
4. Toggle tags or import suggestions.
5. (Optional) select a timeline event to link (`eventId` stored).
6. Hit **Save Annotation**: state resets and the entry appears in the right column.

Callbacks:

- `onAnnotationCreate` emits the saved payload.
- `onExport` (optional) overrides default markdown download behavior.

## Markdown Export

`buildAnnotationMarkdownReport` assembles sections conditionally:

- Summary + session metadata
- Device info block
- Annotation list sorted by timestamp
- Timeline extract (formatted relative to session start)
- Performance snapshot
- Configurable footnote (e.g., "Generated by Punch Club Playtest Annotation Assistant")

Example trigger inside the component:

```ts
const markdown = buildAnnotationMarkdownReport({
  annotations,
  session,
  events,
  config: resolvedConfig,
});
```

If `onExport` is omitted the component produces and downloads a `.md` file via `Blob` / `URL.createObjectURL`.

## Integration Checklist

1. **Hook Up Logger**: pass the existing `PlaytestLogger` instance from `PlaytestPanel` (or keep default singleton).
2. **Config Overrides**: supply product-specific config via `config` prop or rely on defaults.
3. **Placement**: embed inside the playtest tools layout; component is self-contained and only needs CSS to match Observatory styling.
4. **Persistence**: annotations live in memory for this first release. Future work can wire into `PersistenceService` once requirements solidify.
5. **Telemetry (future)**: hook `onAnnotationCreate` / `onExport` to analytics events when needed.

```tsx
<PlaytestAnnotationAssistant
  className="punch-playtest-pane"
  logger={logger}
  config={{ timeline: { refreshIntervalMs: 750 } }}
  onAnnotationCreate={(annotation) => queueReport(annotation)}
  onExport={(markdown) => saveData('last-annotation-report', markdown)}
/>
```
