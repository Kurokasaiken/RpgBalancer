# Minimal Gameplay Risk Heatmap Export

**Prompt:** NP-MIN-PLAN-210 · **Owner:** Risk-Scribe · **Last updated:** 2026-02-12

## Overview

The Minimal Risk Heatmap Export CLI analyzes Minimal Gameplay snapshots (NP-MIN-PLAN-206 schema) and config thresholds from `minimalGameplayConfig.ts` to produce:

- A 10×10 grid of fatigue vs. food days buckets (JSON + CSV)
- Severity breakdowns (Safe / Caution / Danger) per cell
- Summary KPIs (avg fatigue, avg food %, severity score, resident lists)
- A sample JSON export stored in `data/exports/idleVillage/minimal-risk-heatmap-sample.json`

This tool enables QA and designers to inspect resident risk states offline and import the results into spreadsheets or Observable dashboards.

## CLI Usage

```bash
# Basic usage with in-repo config
npx tsx scripts/idleVillage/minimalRiskHeatmapExport.ts \
  --snapshot tmp/sample-minimal-snapshot.json

# Custom config + explicit output targets
npx tsx scripts/idleVillage/minimalRiskHeatmapExport.ts \
  --snapshot data/exports/minimal-snapshot.json \
  --config data/exports/minimal-config.json \
  --output-json test-results/np-min-plan-210-risk-heatmap.json \
  --output-csv test-results/np-min-plan-210-risk-heatmap.csv \
  --verbose
```

### Arguments

| Flag | Description |
| --- | --- |
| `-s, --snapshot <path>` | Snapshot JSON generated by NP-MIN-PLAN-206 serializer (**required**). |
| `-c, --config <path>` | Optional Minimal Gameplay config export. Defaults to bundled config. |
| `--output-json <path>` | Custom JSON output path. Defaults to `test-results/np-min-plan-210-risk-heatmap-<ts>.json`. |
| `--output-csv <path>` | Custom CSV output path. Defaults to `test-results/np-min-plan-210-risk-heatmap-<ts>.csv`. |
| `-v, --verbose` | Print debug logs and summary metrics. |
| `-h, --help` | Display help message. |

## Output Files

1. **JSON Heatmap** – structured data for automation and tooling.
2. **CSV Heatmap** – ready for Excel/Sheets/Observable imports.
3. **Sample JSON** – automatically mirrors the latest run to `data/exports/idleVillage/minimal-risk-heatmap-sample.json` for sharing with designers.

### JSON Schema (excerpt)

```jsonc
{
  "generatedAt": "2026-02-12T13:55:02.123Z",
  "snapshotMetadata": { "version": "1.0", "summary": { ... } },
  "configVersion": "0.1.0-minimal-gameplay",
  "thresholds": { "fatigueDangerPercent": 0.7, "foodDangerDays": 2, ... },
  "grid": [
    [
      {
        "fatigueBucket": 0,
        "foodBucket": 9,

        "averageFatigue": 0.15,
        "averageFoodPercent": 0.95,
        "residents": ["Aurora"]
      }
    ]
  ],
  "summary": {
    "totalResidents": 3,
    "severityCounts": { "safe": 1, "caution": 1, "danger": 1 },
    "averageFatigue": 0.55,
    "averageFoodPercent": 0.62,
    "dangerResidents": ["Cassia"],
    "cautionResidents": ["Balthazar"],
    "severityScore": 0.5
  }

```

### CSV Columns

| Column | Description |
| --- | --- |
| `food_bucket`, `fatigue_bucket` | 0–9 indices for the 10×10 grid. |
| `food_range_*`, `fatigue_range_*` | Inclusive/exclusive bucket ranges (0–1 scale). |
| `resident_count` | Residents mapped to the cell. |
| `safe/caution/danger` | Counts per severity bucket. |
| `avg_fatigue`, `avg_food_percent` | Cell averages for quick visualization. |

## Interpreting the Heatmap

- **Danger bucket**: triggered when fatigue ≥ config threshold (default 70%) **or** food days ≤ threshold (default 2 days). These residents require immediate rest or supply runs.
- **Caution bucket**: 70% of danger threshold (fatigue) or 1.5× food danger days. Watch closely and plan reassignment.
- **Safe bucket**: Well within configured limits.

### KPI Glossary

- **Severity Score**: 0 (safe) → 1 (danger). Average of resident-level severity weights (Safe=0, Caution=0.5, Danger=1).
- **Danger/Caution Resident Lists**: Quick filters for roster management and telemetry tagging.
- **Average Food %**: Food days normalized to twice the `foodDangerDays` threshold.

## Importing into Other Tools

### Excel / Google Sheets

1. Run the CLI to produce the CSV.
2. Import via "Data → Import CSV" and enable headers.
3. Use pivot tables or conditional formatting to create heatmap visuals.

### Observable / Vega Lite

1. Load the JSON output.
2. Bind `foodBucket` to the Y axis, `fatigueBucket` to X.
3. Color-encode by `severityBreakdown.danger` or `residentCount`.

## Maintenance Notes

- Severity logic is config-first: adjust `config.ui.thresholds` to tweak bucket definitions.
- The CLI consumes snapshots only; **never** read directly from Zustand stores.
- Keep tests in `tests/unit/scripts/MinimalRiskHeatmapExport.test.ts` up to date when changing CLI output structure.
- When publishing new heatmap samples, attach the `test-results/np-min-plan-210-risk-heatmap-<ts>.log` evidence link to the Kanban row.
