# Minimal Evidence Pipeline

This document describes the Minimal Evidence Packager CLI and the evidence collection pipeline for Minimal Gameplay prompts.

## Overview

The Minimal Evidence Pipeline provides a standardized way to collect, validate, and package safeguard outputs (lint, test, build) from Minimal Gameplay prompt implementations. The pipeline ensures evidence integrity through checksum validation and generates both machine-readable JSON and human-readable Markdown reports.

## Architecture

### Components

- **`minimalEvidencePackager.ts`**: Main CLI tool for evidence aggregation
- **File Validation**: Ensures all required input files exist and are readable
- **Checksum Generation**: SHA256 checksums for integrity validation
- **Output Generation**: JSON and Markdown evidence packages
- **Test Suite**: Comprehensive testing with mocked file system

### Data Flow

```
Input Files (lint.txt, test.txt, build.txt)
    ↓
File Validation & Reading
    ↓
Checksum Generation
    ↓
Evidence Packaging
    ↓
JSON + Markdown Generation
    ↓
Output Files (evidence.json, evidence.md)
```

## Usage

### Basic Command

```bash
npm run minimal-evidence-packager -- \
  --prompt NP-MIN-STRAT-001 \
  --lint lint.log \
  --test test.log \
  --build build.log
```

### With Notes

```bash
npm run minimal-evidence-packager -- \
  --prompt NP-MIN-STRAT-001 \
  --lint lint.log \
  --test test.log \
  --build build.log \
  --notes "All tests passed, ready for production"
```

### Help

```bash
npm run minimal-evidence-packager -- --help
```

## Command Line Options

| Option | Required | Description | Example |
|--------|----------|-------------|---------|
| `--prompt <ID>` | Yes | Prompt identifier | `NP-MIN-STRAT-001` |
| `--lint <file>` | Yes | Path to lint output | `lint-results.txt` |
| `--test <file>` | Yes | Path to test output | `test-results.txt` |
| `--build <file>` | Yes | Path to build output | `build-results.txt` |

## Integration with Kanban

### Workflow Integration

1. **Complete Implementation**: Finish prompt implementation
2. **Run Safeguards**: Execute lint, test, build checks
3. **Collect Outputs**: Save safeguard outputs to files
4. **Package Evidence**: Run evidence packager CLI
5. **Update Kanban**: Mark prompt as "Completato" with evidence link

### Example Workflow

```bash
# Run safeguards and save outputs
npm run lint 2>&1 | tee lint-results.txt
npm run test 2>&1 | tee test-results.txt
npm run build:check 2>&1 | tee build-results.txt

# Package evidence
npm run minimal-evidence-packager -- \
  --prompt NP-MIN-STRAT-001 \
  --lint lint-results.txt \
  --test test-results.txt \
  --build build-results.txt \
  --notes "All safeguards passed successfully"

# Files created:
# - test-results/NP-MIN-STRAT-001-evidence.json
# - test-results/NP-MIN-STRAT-001-evidence.md
```

## Checksum Validation

### SHA256 Checksums

All files and the overall package include SHA256 checksums for integrity validation:

- **File Checksums**: Validate individual file contents
- **Package Checksum**: Validate overall evidence package structure

### Validation Process

1. **File Reading**: Read all input files
2. **Individual Checksums**: Generate SHA256 for each file
3. **Package Checksum**: Generate SHA256 for package metadata
4. **Output Generation**: Include checksums in JSON and Markdown

### Deterministic Checksums

Checksums are deterministic for identical content, enabling:
- **Integrity Verification**: Detect file corruption
- **Change Detection**: Identify when outputs have changed
- **Audit Trail**: Prove evidence authenticity

## Error Handling

### File Validation Errors

- **Missing Files**: Clear error messages for missing required files
- **Read Errors**: Handle file system read failures
- **Path Validation**: Ensure valid file paths

### Example Error Messages

```
Required lint file not found: /path/to/missing-lint.txt
Required test file not found: /path/to/missing-test.txt
Required build file not found: /path/to/missing-build.txt
```

### Recovery

- **Retry**: CLI can be re-run with corrected file paths
- **Validation**: Check file existence before running safeguards
- **Logging**: All errors are logged with context

## Best Practices

### File Organization

- **Input Files**: Store safeguard outputs in consistent locations
- **Output Files**: Use `test-results/` directory for evidence packages
- **Naming Convention**: `{prompt}-evidence.{json|md}`

### Content Guidelines

- **Lint Output**: Include full eslint output with error codes
- **Test Output**: Include vitest summary with pass/fail counts
- **Build Output**: Include TypeScript compilation results

### Notes Usage

- **Use Notes**: For additional context about test runs
- **Version Info**: Include relevant version numbers
- **Environment**: Note testing environment details

## Troubleshooting

### Common Issues

#### "File not found" errors
**Solution**: Verify file paths and ensure safeguards have been run

#### Checksum mismatches
**Solution**: Re-run safeguards to regenerate outputs

#### CLI argument errors
**Solution**: Use `--help` to verify correct syntax

### Debug Mode

Enable verbose logging by modifying the CLI script:

```typescript
// In minimalEvidencePackager.ts
console.log('📦 Packaging evidence for prompt:', prompt);
```
