# Archmage Fight: Principles (Jan 2026)

## 1. Obiettivo Core

Creare un combattimento a carte che:

- premia decisioni qualitative (non solo numeriche);  
- costringe il giocatore a rivalutare il piano iniziale (model revision);  
- genera emergent gameplay guidato, non caos casuale;  
- mantiene leggibilità sotto stress e controllo cognitivo.

## 2. Principi Psicologici (Positivi)

### 2.1 Stato (cognitive foundations)

| Principio | Applicazione |
| --- | --- |
| **Locus of Control** | Il giocatore percepisce che l’outcome dipende dalle proprie scelte (bias, reroll, preview). |
| **Flow State** | Challenge = skill + 10‑15%; ogni turno 1 decisione core + 1‑2 ottimizzazioni con feedback immediato. |
| **Variable Ratio Reinforcement** | Reward distribuito (piccolo/medio/grande), outcome spectrum crit/accessorio, mai binario. |
| **Peak-End Rule** | Match progettato per pivot/piani da rivedere ogni 3‑4 turni. |
| **Cognitive Closure** | Post-match “perché ho perso/vinto” in <30s. |
| **Temporal Discounting** | Progress/micro-reward ogni 1‑2 turni. |
| **Skill Expression Gradient** | Outcome 0‑100%, non hit/miss. |
| **Narrative Coherence** | Gli effetti raccontano micro-storie coerenti con la situazione di board. |

### 2.2 Dinamicità

| Principio | Applicazione |
| --- | --- |
| **Error Recovery Elasticity** | Recupero proporzionato: 1 turno (errore small) / 2‑3 (medium) / 4‑6 (grave, non garantito). |
| **Tension Curve Smoothness** | Crescita ondulata, no spike serrati (varianza tensione controllata). |
| **Option Relevance Ratio** | 3‑5 opzioni plausibili, altre chiaramente secondarie. |
| **Expectation Violation Quality** | Surprise istruttiva (“ok, ora ho capito”), non tradimento. |
| **System Legibility under Stress** | Chiarezza anche quando sei in svantaggio (drop accuratezza <15%). |

### 2.3 Trasformativo / Emergenza guidata

| Principio | Applicazione |
| --- | --- |
| **Emergent Gameplay Guidato** | Il board cambia qualitativamente, il piano originale diventa inefficace. |
| **Dynamic Decision Context** | Spell/nemici/gimmick modificano come leggi il board. |
| **Second-Order Thinking** | Il player anticipa catene X → Y → Z. |
| **Adaptive Decision Environment** | Valore azioni dipende dal contesto, non è fisso. |

### 2.4 Costrutti psicologici referenziati

| # | Costrutto | Fonte | Implicazioni per ArchMage |
| --- | --- | --- | --- |
| 1 | **Mental Model Theory** | Johnson-Laird, 1983 | Il loop core è “distruggere e ricostruire” il mental model del giocatore: il gioco è interessante quando il modello diventa falso, non quando crescono i numeri. |
| 2 | **Model-Based vs Model-Free Decision Making** | Daw et al., 2005 | ArchMage deve restare model-based: carte “goodstuff” o always-optimal annullano il ciclo cognitivo. |
| 3 | **Representational Change Theory** | Ohlsson, 1992 | Insight = cambiare rappresentazione del problema. Ogni spell traslativa deve far “leggere diversamente” board/stat. |
| 4 | **Affordance Reinterpretation** | Gibson, 1977 / Norman, 1988 | L’oggetto non cambia, cambia cosa ti permette di fare. Le spell mantengono testo ma mutano affordance in base al contesto. |
| 5 | **Decision Framing/Reframing** | Tversky & Kahneman, 1981 | Board shifting = reframing forzato: “questa non è più la decisione che pensavo”. |
| 6 | **Dynamic Choice Architecture** | Thaler & Sunstein, 2008 | Le scelte e il loro valore cambiano nel tempo (spell che scadono, ritardi, pressione temporale). |
| 7 | **Second-Order Decision Making** | Theory of games | Non scegli l’azione migliore, ma quella che apre lo spazio decisionale migliore dopo. |
| 8 | **Option Value Theory** | Real options | Le spell “deboli” valgono perché mantengono opzioni future: no payoff immediato obbligatorio. |
| 9 | **Temporal Uncertainty as Engagement Driver** | Behavioral econ / game studies | “Quando succede?” > “Quanto fa?” → supporta risoluzioni posticipate e accumulo rischioso. |
| 10 | **Legibility under Stress** | Rosewater / Valve / Bungie UX | Il sistema deve restare leggibile quando sei in svantaggio. |
| 11 | **Negative Capability (design)** | Keats → systemic design | Il sistema non dà soluzioni ma resta interpretabile. |
| 12 | **Cognitive Economy** | Simon, 1955 | Poche regole, eccezioni significative, niente stack infiniti. |
| 13 | **Error-Based Learning** | Rescorla–Wagner | Si impara se l’errore è attribuibile: RNG opaco distrugge l’apprendimento. |
| 14 | **Counterfactual Thinking** | Roese, 1997 | Dopo ogni match il player deve poter dire “se avessi fatto X…”. |
| 15 | **State-Space Compression** | AI planning / cog. science | Ridurre lo stato a poche configurazioni qualitative (traslazioni di contesto, non scaling continuo). |

## 3. Principi Psicologici (Negativi – da evitare)

### 3.1 Stato

| Principio | Effetto |
| --- | --- |
| **Loss Aversion** | Perdere percepito 2× peggio: evitare decay senza gain-loop. |
| **Learned Helplessness** | Outcome incontrollabile → frustrazione. |
| **Analysis Paralysis** | >7 opzioni simultanee = blocco decisionale. |
| **Endowment Effect** | Hoarding risorse se lo spend è punito. |
| **Regret Aversion** | Errori che perseguitano mentalmente (early irreversibili). |
| **Cognitive Load** | Troppe variabili da trackare (>7). |
| **Anchoring Bias** | Primo dato distorce giudizio. |
| **Sunk Cost Fallacy** | Investimento passato vincola scelte future. |

### 3.2 Dinamicità

| Principio | Effetto |
| --- | --- |
| **Snowball / Rubber-band Extremes** | Early advantage incontrollabile o inutile. |
| **Mastery Plateau Deadzone** | Skill ceiling troppo basso. |
| **Volatility Whiplash** | Delta emotivo troppo alto tra turni. |

### 3.3 Anti-Trasformativo

| Principio | Effetto |
| --- | --- |
| **Spreadsheet Optimization** | Gameplay ridotto a calcolo numerico. |
| **Goodstuff Syndrome** | Carte sempre ottime, zero adaptive thinking. |
| **Emergenza Casuale Non Guidata** | Interazioni impreviste → caos. |
| **False Complexity** | Tante opzioni identiche → illusione profondità. |

## 4. Metriche di Validazione

- **Stato:** Agency Score >95%, Surprise Delight 20‑30%, Regret Density 10‑15%, Mental Model Accuracy 60‑70%, Decision Time <30s.  
- **Dinamicità:** Error recovery proporzionato (1 / 2‑3 / 4‑6 turni), Tension slope <30%, 3‑5 plausible options, Legibility decay <30%, Comeback win 15‑25%.  
- **Trasformativo:** Plan invalidation rate 30‑40% dei turni, 2‑4 strategic pivot per combat, spell contextual variance alta, interaction density 2‑3 trigger per elemento, model revision frequency 3‑5 per combat.

## 5. Checklist Trasformativo / Design Decision

**È trasformativo?**

- ❌ Solo numeri più grandi / bonus condizionale che non cambia piano.  
- ✅ Cambia valore relativo delle altre spell, invalida il piano corrente, apre nuova linea.

**Cognitive load?**

- ✅ Trigger chiaro (<3 condizioni), interazioni limitate (2‑3 elementi), payoff leggibile.  

**Adaptive thinking?**

- ✅ Spell con purpose diverso per contesto, né sempre ottimali né sempre inutili, richiede model revision.  

**Legibility under stress?**

- ✅ Visibile e comprensibile anche in losing scenario, senza calcoli nascosti.

## 6. Design Elements

- **Player**
  - *Mana / risorse:* slot + pool permanente; limita cosa casti e rende le scelte non banali.  
  - *Azione baseline:* sempre disponibile (fisica o rituale).  
  - *Difese:* HP, DR, dodge, armor = bonus numerici, non trasformativi.

- **Nemici**
  - Piani chiari, risorse variabili, counterspell possibile.  
  - Build/archetipi diversi → le loro azioni generano risposte trasformative.

- **Equip**
  - Trasformativo: fornisce spell/modifica qualitativamente il board.  
  - Non trasformativo: armor solo bonus HP/DR.

- **Spell**
  - Trasformativo: cambia contesto, ha purpose diverso per scenario, triggera interazioni.  
  - Non trasformativo: buff temporanei, moltiplicatori, scaling numerico puro.

## 7. Mini-Simulation (Next Step)

- **Setup:** 3 spell con purpose contestuale, 2 nemici (pattern diversi), mana system, 1‑2 gimmick trasformative.  
- **Test objectives:** identificare interazioni trasformative, validare plan invalidation, misurare cognitive load + legibility, garantire emergenza guidata.  
- **Success criteria:** ≥2 pivot point/run, valore spell cambia ≥30% tra scenari, decision time <30s anche durante transformation, player capisce “perché ho perso” in <30s.

> **Nota critica:** i parametri dinamici non vanno massimizzati simultaneamente; mantenerli in tensione preserva la vitalità del sistema.

## 8. Esempi di gameplay traslativo emergente

| Scenario | Perché è traslativo |
| --- | --- |
| **Death’s Shadow (MTG)** | La carta diventa più potente man mano che perdi vita: il board assume significato diverso in base a uno stato esterno (vita). |
| **Chip del poker** | Le chip influenzano bluff/call/fold: la risorsa cambia strategia, non solo numeri. |
| **Diventare un pesce sulla mappa** | Muovi solo in acqua: il modo di leggere lo spazio cambia completamente. |
| **Calice del Nulla (versione traslativa)** | Es. “le spell a costo 1 ora curano l’avversario”: non vieti, ma crei costo di opportunità e rivalutazione delle scelte. |
| **Non-morto: healing fa danno, danno cura** | Inverte le regole standard: bisogna rivalutare ogni azione offensiva/difensiva. |
| **Guard stile Street Fighter** | Se blocchi X attacchi ottieni stun gratuito → timing e uso difesa/offesa cambiano contesto. |
| **Convergenza di stato / slot modificati** | Slot/risorse assumono nuovi scopi a seconda del board, forzando riprioritizzazione delle spell. |
| **Spell con risoluzione posticipata** | Le spell si risolvono il turno successivo (con possibilità di pagare HP per anticipare): ridefinisce priorità e rischio. |
| **Cambio classe con payoff di altra classe** | Cambia tipo di risorsa e condizioni di vittoria: il piano originale non vale più. |
