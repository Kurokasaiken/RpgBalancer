# Translation Guide

## Purpose

This guide is the primary reference for translators, LQA specialists, and TMS administrators working on the RPG project. It covers tone of voice, glossary, abbreviations, style rules, and technical instructions for importing and exporting translation files.

---

## Tone and Voice

- **Atmosphere**: medieval, low-fantasy, slightly archaic without being archaic to the point of inaccessibility.
- **Formality**: polite but direct. Avoid slang and modern idioms.
- **Player focus**: address the player implicitly through UI labels. Use second person only when the narrative explicitly speaks to the player.
- **Consistency**: keep terms for core concepts (classes, resources, actions) identical across namespaces.

## Glossary

| Term | Category | Notes |
|------|----------|-------|
| Resident | Idle Village | A character assigned to village activities. Do not use "villager" or "worker" unless the source key explicitly says so. |
| POI | Idle Village | Point of Interest; can be left as POI in most languages. |
| Gold | Currency | Standard fantasy currency. |
| Food | Resource | Village resource, not generic "food". |
| Fatigue | Stat | Translates as a measurable condition. |
| HP | Stat | Health Points; keep the abbreviation unless the language has a well-known localized equivalent. |
| STS | Combat | Slay the Spire-inspired subsystem; acronym stays. |
| Slot | UI | A slot in a rack or POI. |
| Capsule | UI | Activity capsule UI element. |

## Abbreviations

- **HP**: Health Points.
- **TTK**: Time to Kill.
- **DPT**: Damage Per Turn.
- **FTUE**: First Time User Experience.
- **POI**: Point of Interest.
- **LQA**: Localization Quality Assurance.

Keep abbreviations identical across languages unless the target language has a widely accepted local acronym. When localizing, expand the abbreviation in the `context` note if needed.

## Style Guide

1. **Use ICU MessageFormat** for plural, select, and variable interpolation.
   - Example plural: `{count, plural, one {one slot} other {{count} slots}}`.
   - Example select: `{gender, select, male {his} female {her} other {their}}`.
2. **Never concatenate fragments**. Use named placeholders and full sentences.
3. **Capitalization**: use sentence case for labels and tooltips. Use title case for titles, section headers, and named locations.
4. **Punctuation**: keep trailing punctuation consistent with the source string. If the source has no period, do not add one.
5. **Max length**: respect `maxLength` and `size-unit` attributes in XLIFF. If the limit is too tight, add a comment to the TMS and propose a shorter alternative.
6. **Variables**: do not translate placeholder names inside `{...}`. Preserve the exact variable name.
7. **Text expansion**: German can expand up to 40% longer than English; Romance languages 20-30%. Design for expansion, and use `maxLength` to flag tight UI strings.

## TMS Integration

### Source Files

- English source bundles are in `public/locales/en/*.json`.
- Optional metadata (context, maxLength, description) is in `public/locales/en/*.meta.json`.
- Do not edit `public/locales/pseudo/*.json` manually; they are generated by `npm run i18n:build-pseudo`.

### Export to XLIFF

```bash
npm run i18n:export
```

- Generates `dist/i18n/tms-export/en/<namespace>.xlf`.
- Each XLIFF file is XLIFF 1.2 with `context` and `maxLength` notes preserved.
- Upload the generated files to your TMS (Crowdin, Lokalise, Tolgee, etc.).

### Import from XLIFF or PO

Place translated files from your TMS in:

```
dist/i18n/tms-import/<locale>/<namespace>.xlf
# or
dist/i18n/tms-import/<locale>/<namespace>.po
```

Then run:

```bash
npm run i18n:import
```

This merges translations into `public/locales/<locale>/<namespace>.json` and preserves metadata in `*.meta.json`. Existing keys are updated only when the target value is non-empty.

### Vendor-Specific CLI Notes

- **Crowdin**: Use `crowdin upload translations` after copying `dist/i18n/tms-export/en/*.xlf` to your Crowdin source folder. Download back to `dist/i18n/tms-import/<locale>/`.
- **Lokalise**: Upload the XLIFF files through the web UI or `lokalise2 file upload`. Download translated XLIFF into the import directory.
- **Tolgee**: Use the Tolgee CLI to push and pull `.json` files directly; run `i18n:export` and `i18n:import` as a bridge for the legacy `public/locales` layout.

Never commit API keys or TMS credentials in this repository.

## LQA Mode

Enable LQA mode in development to inspect keys in the UI:

```
http://localhost:5173/?lqa=true
```

The LQA overlay displays keys, source strings, target strings, context, and maxLength. It is not included in production builds.

## Validation

After import, run the validation suite:

```bash
npm run i18n:validate
npm run i18n:build-pseudo
npm run build:check
```

`i18n:validate` checks that all keys used in source code are present in the English locale.
