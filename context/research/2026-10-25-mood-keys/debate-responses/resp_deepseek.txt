On the two open disputes:

Edit cap — rule FOR 2, against 3. My own round-1 draft said 3; I now withdraw it. The artifact's own degradation signal set (clipped highlights, impasto→glossy, composition drift) is a cumulative failure, and the validated overshoot appears after the first successful edit. If edit #2 is already showing overshoot, edit #3 is being spent on a thread whose base latent is contaminated — and Gemini has no seed to reset from. The "3" only buys value when edits are independent; they aren't. 2 edits, and the second edit must be a register-reinjection edit, not a new target. This makes "3" a false economy that costs a generation and pollutes the attribution log (you can't tell if symptom on edit #3 is field-caused or decay-caused). Concession: allow a 3rd edit only if edit #1 and #2 addressed different fields AND the degradation checklist is clean — i.e. 3 is earned, not default. That's a tighter rule than either draft.

Texture degradation — rule FOR "one corrective edit," but reclassified. Gemini is right that "keep composition, change only texture" is out-of-distribution for an edit instruction — texture is not a target the loop was validated on. But "never editable" is also wrong, because the degradation is attention decay on register vocabulary, not a structural defect; the corrective action is a register re-injection, which is exactly what the edit channel is for. Resolution: texture failure is not an edit target — it is a re-anchor event. Permitted action: same chat, but the message must be a full re-paste of BAPTIZED_STYLE_REGISTER verbatim plus "preserve current composition and lighting," not "change texture to X." If that fails → thread DEAD. This is neither gemini's "never" nor deepseek's "one corrective edit" — it's "one register re-anchor, then dead." Also: this event must be logged as a re-anchor, not an edit, so it doesn't count toward the 2-edit budget and doesn't pollute attribution.

On DOMINANT_COLOR_FIELDS-as-geometric-zones:

Objection — the fix is unsound as written and creates the collision it claims to solve. "Sky occupies upper 60%, meadow lower 40%" is a layout instruction. It sits in field 3, before COMPOSITION (field 5), which means the model receives a compositional commitment before it receives the composition archetype and focal hierarchy. That's an ordering defect: layout declared before the thing that should own layout. Two failure modes I expect: (i) hard horizon at exactly 60% regardless of archetype (eye-level Rude Beauty wants a soft horizon; Impero low-angle wants a compressed ground plane — 60/40 fights both); (ii) focal hierarchy loses to the zone because the zone was named earlier and more concretely. The stated motivation — "zones, not subjects that conflate with creature volume" — is real but the remedy is wrong. Fix: split the field. DOMINANT_COLOR_FIELDS stays as subjects (the lesson-c truth: naming them as palette items drifts; naming them as subjects holds) and zone geometry moves to COMPOSITION as an optional sub-field FIELD_EXTENT only when the archetype needs it. Also add a GATE check: if FIELD_EXTENT is present, it must not contradict focal hierarchy or archetype camera. Zones are a compositional claim; putting them in field 3 is a category error.

On the FORK rule — missing failure mode:

Objection — FORK is missing "right composition, right key, wrong SUBJECT-CLASS READ." Specifically: the image is compositionally correct and the mood reads, but the subject is readable as the wrong class or the wrong role — a creature that reads as a prop, a witness that reads as a protagonist, a quest scene whose action beat is illegible at thumbnail. FORK 1 catches composition/focal, FORK 5 catches anatomy/expression, but neither catches role illegibility (subject present, correctly drawn, but narratively misread). These are regenerates, not edits — you cannot edit "make this read as a witness not a hero" without violating "keep composition." Add FORK 0 or 6: role/subject-read wrong → REGENERATE, and add ROLE_READ to the per-class SUBJECT blocks (creature: prop vs actor; human: witness vs protagonist vs obstacle; quest scene: action beat legible at thumbnail Y/N). Without this, the protocol sends role failures into the edit loop where they will burn the budget and produce overshoot.

Minor objection — FORK ordering vs G7. G7 (ONE-VARIABLE) is a pre-send gate, but FORK decides what kind of generation this is. If FORK routes to REGENERATE, G7 is irrelevant (new baseline). If FORK routes to EDIT, G7 must apply to the edit instruction — i.e., "change only X" must name exactly one field. Artifact doesn't say this; state it explicitly or G7 silently doesn't apply to edits.

No objection to §5 (ablation/conviction-twice), §6 (lifecycle signals), §8 (acceptance-by-seeing). The two-confirmation rule is expensive but correct given no seeds; the "structural pass ≠ mood pass" line is the single most important sentence in the artifact.

Net position: artifact r001 is directionally sound. Must-fix before v6: (a) reclassify texture-degradation as register re-anchor (not edit, not never-edit); (b) resolve cap to "2 default, 3 earned, 3rd must be re-anchor-class"; (c) move zone geometry out of field 3 into COMPOSITION.FIELD_EXTENT; (d) add FORK branch for role/subject-read failure + ROLE_READ sub-field; (e) state G7 applies to edit instructions.
